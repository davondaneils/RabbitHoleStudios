# Script testing and learning from real viewers
Based on the [2026-10-14 evidence review](../../RESEARCH/short-form-scriptwriting-2026-10-14.md). These are practical house procedures; quantities and review windows below are conventions, not scientifically optimal rules.

## Before drafting
Write one audience concern, one promised reward, the actual source-backed story question and the intended takeaway. State the working performance hypothesis: for example, a concrete surprising result may earn an initial watch while a clear causal story preserves understanding. Do not label it proven.

Write a few materially different hooks when useful. Keep the body stable if exploring the opening; changing voice, visuals, duration and story simultaneously prevents useful diagnosis. Choose the candidate opening by truthfulness, immediate clarity and account fit, not an invented retention score.

## Before production
1. Make a separate substantive editorial pass. An independent agent may critique the draft, but disclose that this is model judgment.
2. Record a scratch read in the intended delivery if available. Note actual duration, difficult phrases, rushed qualifications and where a revealing image needs space. Do not call a silent text review a spoken test.
3. Let a few unfamiliar people hear it once without reading the transcript. Ask open questions: what happened; why did the next event follow; what was surprising; what would you check differently afterward? Record the actual answers and misunderstood passage. Avoid leading them to recite our wording. This informal check identifies problems; it is not a representative audience experiment.
4. Check the opening and evidence visuals on a phone, with sound and without it. Subtitles should be readable and coordinated with speech. Audio alone should carry basic who/what/why. Essential visuals should support the scene rather than compete with a second unrelated explanation.
5. Repair concrete problems, preserve source caveats, and present the whole candidate to the founder. Record which checks actually occurred.

Actual voice/listener/visual testing can remain pending at script-candidate delivery if its inputs are unavailable; state that clearly. No publication or spending is authorized by this document.

## After publication approval
Use existing account tools and Trial Reels if suitable. Trial audiences and distribution are not randomized; treat comparisons as exploratory. Keep optional automatic broader sharing off unless intentionally authorized. No paid testing is implied.

Log version, hook premise, duration, voice/visual treatment, posting time, audience/traffic context, reach and each metric's definition. Inspect at roughly 24 and 72 hours, then again if later distribution materially changes. These windows are a consistent observation habit, not an algorithm claim.

| Question | Evidence to inspect | Do not infer |
|---|---|---|
| Did people start watching? | Early skip/stay data where available | A universal threshold or algorithm weight |
| Did interest persist? | Watch time, completion/retention where available; actual passage at drops | Every exit was caused by writing |
| Did the meaning land? | Retell checks and unprompted audience responses about the mechanism | Watching equals understanding |
| Was it useful or shareable? | Shares/saves in context, reasons mentioned, returning-viewer behavior | All shares reflect agreement or buyer interest |
| Did it build account interest? | Follows/profile visits and interest in further cases | Every viewer fits our target segment |
| Did it create buyer demand? | With an actual approved offer: visits, purchases, refunds and relevant feedback | Follows or curiosity prove willingness to pay |

Compare similar formats/lengths and record denominators; cross-platform views use different definitions. A replay may indicate pleasure or confusion. A large reach difference can reflect audience and distribution, not the script alone.

Use repeated patterns across cases before changing a house rule. Decide which variable to test next and why. Do not rewrite endlessly on tiny noisy differences, and do not treat one viral post as proof of a universal technique. Record failures as well as successes so the library reflects actual evidence rather than a collection of attractive formulas.
